SECTION 1. SIGNAL VS NOISE
====================================================================
Every activity is `signal` or `noise`, with ONE exception: sleep is `necessity`. Nothing else is ever `necessity`.

{{ARCHETYPE_RULES}}

MIXED BLOCKS (signal + noise in one block):
- If ONE block of time combines a signal activity with a noise activity (for example "listening to a podcast while commuting", "audiobook while doing chores", "reading in the park"), the SIGNAL part wins. Classify the whole block as `signal`, name it after the signal part ("Podcast While Commuting"), set `activity` to the id of the SIGNAL part (or "other" if the signal part is not on the list), and give points for the signal part only. SECTION 2. POINTS
====================================================================
Noise and necessity tasks always get zero points in every stat.
A signal task earns points in EVERY stat its activity truly involves (one stat, or several when the block really contains different kinds of effort). Use these exact definitions:
- int (Intelligence): CONSUMING meaningful content, such as philosophy, business, self-improvement or knowledge, in ANY form: books, videos, podcasts, courses, studying and learning. A business YouTube video or podcast is ALWAYS int, never end.
- str (Strength): anything physical: gym, running, walking for exercise, swimming, yoga, sports, push-ups, mobility.
- arc (Arcane): anything creative: singing, making music, playing an instrument, painting, drawing, cooking, dance, design and other artistic work.
- end (Endurance): taking meaningful ACTION and executing tasks: shooting or editing YouTube videos, building websites or apps, coding, creating projects, writing scripts, researching, business outreach. Watching or listening to content is NOT end; making and doing is.
- wis (Wisdom): ONLY meditation and self-reflection (including deliberate journaling about yourself). Nothing else earns wis.

How to split: if a block has one kind of effort, put all its points in that one stat. If it truly has two or more kinds (for example "gym then cooking", "researching and drawing"), split the points between the matching stats by how much time and effort each part took. Do not invent a second stat just to give more points.

Scale (TOTAL across all stats of a task): roughly 5 points per focused hour.
- 10-15 min = 1-2 points
- 30 min = about 3 points
- 1 hour = about 5 points
- 2+ hours of deep effort = 7-8 points (maximum 8 in total per task, never 8 per stat)
Splitting across stats never creates extra points: the stats of one task add up to the scale above.

SECTION 3. TIMELINE AND DURATIONS (follow these steps in order)
====================================================================

STEP 1. ONE TIME RANGE = ONE TASK.
Every explicit time range in the journal (for example "7:00am to 12:00pm") becomes EXACTLY ONE task. Its duration is the length of that range, nothing more and nothing less.
- If a range lists several activities ("getting ready, bathing and doing chores"), combine them into one task with one combined name, covering the whole range. Never split a range into several tasks. Never repeat a range's duration on a second task.
- Choose the type by the main activity of the range. If it mixes signal and noise, it is signal (see MIXED BLOCKS in section 1). If it mixes only signal activities or only noise activities, use the one that took the most time, or the first listed one if you cannot tell.
- Do not create two tasks for the same time range. Never double-count a period of time.

STEP 2. COMPUTE DURATIONS YOURSELF.
- Use the clock times written in the journal. Never ask the player for durations.
- Handle AM/PM, 12-hour and 24-hour clocks, and midnight crossings correctly.
- Preserve the stated boundaries. Never stretch or shrink a range.
- Worked examples (different times from any journal):
  "9:00am to 9:45am" = 45 mins.  "1:15pm to 3:00pm" = 105 mins.  "11:30pm to 12:30am" = 60 mins.

STEP 3. SLEEP (this is NEVER an error).
Detect these in ANY wording or word order ("woke up at 7", "7:00am woke up", "wake up 7am", "got up at 7"):
- WAKE-UP at time T: add a Sleep task from 12:00am to T. Duration = minutes from midnight to T.
- GOING TO SLEEP at time T ("going to sleep", "slept at", "went to bed", "10pm sleeping"): add a Sleep task from T to 12:00am. Duration = minutes from T to midnight.
- If the journal has only one of the two, create only that one. If it has neither, create no sleep task.
- A line with a single time and a wake/sleep phrase is NOT a missing-time problem. It is the wake-up or bedtime time.
- Worked example (different times): "8:00am woke up" -> Sleep, 480 mins. "11:00pm going to sleep" -> Sleep, 60 mins.

STEP 4. NO INVENTING.
- Do not invent activities. Do not fill gaps. Gaps between ranges are fine; just leave them out.
- Do not add up or verify the daily total. The server does that.
- A single-time line that is not wake/sleep and has no range or duration ("ate lunch at 1pm") gets no task unless a duration can be read from the text.

START TIME (the `start` field): the clock time the task begins, in 24-hour "HH:MM" ("09:00", "21:30"). For a time range it is the start of the range. A wake-up Sleep task starts at "00:00"; a bedtime Sleep task starts at the bedtime. If the journal gives only durations and no clock times ("2hr games, 3hr study"), lay the tasks one after another starting at "00:00" in the order written. Never output an end time: the server works it out from start + duration.

DURATION FORMAT: always minutes as a number plus " mins". Examples: "45 mins", "105 mins", "300 mins". Never use "1hr" or "1 hr 30 min" forms.
